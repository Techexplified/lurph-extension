# Lurph AI Chrome Extension

React + Vite frontend for the Lurph Chrome extension. Supports email/password authentication and Passport.js Google OAuth through Chrome Identity.

## Configure the frontend API URL

Copy `.env.example` to `.env` and set the backend URL:

```env
VITE_API_BASE_URL=http://localhost:4000
```

The URL must be the base origin of the Express API, without a trailing slash.

## Google OAuth flow

1. The user clicks **Continue with Google**.
2. The extension calls `chrome.identity.launchWebAuthFlow()` with `GET /api/auth/google`.
3. Passport redirects to Google and then returns to the extension's `chrome.identity.getRedirectURL()` callback with a one-time code.
4. The frontend sends that code to `POST /api/auth/google/exchange`.
5. The returned Lurph access and refresh tokens are saved using the existing token storage and the authenticated UI is shown.

Google sign-in requires the **built extension loaded in Chrome**; it does not run from the ordinary Vite page because `chrome.identity` is not available there.

## Install and build

```bash
npm install
npm run dev
```

For extension OAuth testing, build and load the generated `dist` folder from `chrome://extensions` with Developer mode enabled:

```bash
npm run build
```

## Chrome extension permissions

`public/manifest.json` includes the `identity` permission and a host permission for local development at `http://localhost:4000/*`. If your backend is hosted elsewhere, add its exact origin to `host_permissions` (for example, `https://api.example.com/*`) before rebuilding.

## Backend configuration

The backend `.env` must contain:

- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` for a Google OAuth **Web application** client.
- `GOOGLE_CALLBACK_URL`, registered as an Authorized redirect URI in Google Cloud Console (for local testing, `http://localhost:4000/api/auth/google/callback`).
- `GOOGLE_EXTENSION_REDIRECT_URL`, exactly matching the URL generated by `chrome.identity.getRedirectURL()` for the loaded extension. It usually resembles `https://<extension-id>.chromiumapp.org/`.
- `CORS_ORIGINS`, including the extension origin `chrome-extension://<extension-id>` and `http://localhost:5173` if using Vite for non-OAuth development.

If you change the extension ID, update `GOOGLE_EXTENSION_REDIRECT_URL` on the backend and reload/rebuild the extension as needed.

## Connected routes

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/google`
- `GET /api/auth/google/callback`
- `POST /api/auth/google/exchange`
- `GET /api/auth/me`
- `POST /api/auth/refresh` (automatic token refresh)
- `POST /api/auth/logout`

Access and refresh tokens use the existing `chrome.storage.local` implementation in the extension, with a `localStorage` fallback for regular Vite development. The frontend never receives Lurph tokens in the OAuth URL; it exchanges a short-lived, single-use code with the backend.


## First-install and onboarding flow

- On first installation, the extension opens `index.html` in a tab. Unauthenticated users see the sign-in/create-account screen.
- After successful email/password or Google sign-in, first-time users see the three onboarding steps in order: Welcome, Permissions & Privacy, and You're all set.
- The Continue button on the permissions step requests optional access to websites through Chrome's native permission prompt. If permission is denied, onboarding can still finish and the screen explains where to enable access later.
- The final Start using Lurph button saves `lurph_onboarding_completed` in extension storage and closes the setup tab. The welcome flow is not shown again after completion.
- The toolbar icon can be clicked any time to reopen the extension page. Chrome requires users to pin the icon manually from the Extensions menu.

### Before production build

Set `VITE_API_BASE_URL=https://lurph-extension-backend.vercel.app` in the frontend environment before running `npm run build`. The manifest includes that backend host and localhost for development, plus optional `<all_urls>` website access requested only after the user clicks Continue.
